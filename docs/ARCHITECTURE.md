# Runtime Architecture

Vanilla JS, no build step. Every file is an IIFE assigned to a top-level `const` global, loaded by `<script>` tags in [index.html](../index.html). Load order (must be preserved):

```
jspdf (CDN 2.5.1)
js/utils.js            → TakeoffUtils
js/events.js           → TakeoffEvents   (telemetry; dual browser/Node, reads the endpoint from cloud.js at flush time)
js/toast.js            → TakeoffToast    (the one feedback region; no deps)
js/data/fittings.js    → FITTINGS_LIST
js/data/laborBookDefaults.js → LABOR_BOOK_DEFAULTS, LABOR_BOOK_DEFAULT_GROUPS, LABOR_BOOK_DEFAULTS_VERSION
js/laborBookMerge.js   → TakeoffLaborBookMerge (defaults merge + corrections diff; dual browser/Node)
js/storage.js          → TakeoffStorage  (persistence adapter)
js/uiState.js          → TakeoffUiState  (ephemeral UI state; re-exported by TakeoffState)
js/selectors.js        → TakeoffSelectors (pure manifest selectors; dual browser/Node)
js/cloudSync.js        → TakeoffCloudSync (project sync/push decisions; dual browser/Node)
js/state.js            → TakeoffState
js/import.js           → TakeoffImport
js/elliotPriceCore.js  → McElliotCore   (dual browser/Node)
js/mcElliotState.js    → McElliotState
js/mcElliotMatch.js    → McElliotMatch
js/mcElliotUpdate.js   → McElliotUpdate
js/mcBook.js           → McBook
```

Only `TakeoffApp` is explicitly on `window`; the rest are top-level `const` (visible cross-script via global lexical scope, but **not** `window.X` properties).

Three files sit outside that load order, at the repo root so GitHub Pages serves them at the site root:

| File | What |
|---|---|
| `sw.js` | App-shell service worker. Precaches `index.html`, `css/styles.css` and every same-origin `js/` file — **read out of index.html at install time**, not listed twice, so a new `<script>` tag needs no edit here. Navigations and shell assets are network-first with the cache as the offline fallback; the six `mc-assemblies/*.json` the app fetches are cache-first with a background refresh (12 MB together, so they land on first use rather than at install). Anything cross-origin (Supabase, jsDelivr/cdnjs, Google Fonts) is never intercepted and never cached |
| `manifest.webmanifest` | Web app manifest — `short_name` "Takeoff", `start_url` ".", `display: standalone`, colours from the `css/styles.css` palette (`--bg` `#0f0f11`), icons from `icons/` |
| `icons/icon-{192,512}.png` | Generated by `python3 scripts/make-icons.py` (pure stdlib, no Pillow). Re-run after a palette change |

`js/app.js` registers the worker at the tail of init, guarded by `'serviceWorker' in navigator`, `location.protocol !== 'file:'` and `!navigator.webdriver` — see the quirk below.

## State (`js/state.js`, `TakeoffState`)

### Manifest item (canonical shape)

```js
{ id,                    // 'id_' + Date.now() + '_' + rand
  type,                  // string|null — see type lists below
  description, quantity,
  labor,                 // per-unit hours (number)
  price,                 // number|null
  planPage,              // string
  parentId,              // string|null
  children,              // [item] — max depth 2 (getItemById only searches top + children)
  conduitMeta, meta }    // meta: trenching {feet, material, depth, pricePerFoot}; overage {overagePercent}
                         //       trenchingAddon {addonGroup: 'rental'|'fill'} — which button group added it
                         //       book {type, section, name, partNumber?} — the Labor & Price Book row this
                         //       row came from (X1); priceSource/pricedAt — where its money came from
```

Top-level `type` values (`ITEM_TYPES`): `lighting gear devices conduit wire specialSystems permits powerCoCharges temporaryPower`.

Child `type` values by flow:
- **devices**: `outletsAndSwitches box backBoxSupport cover conduit wire screws misc`
- **conduit**: `trenching trenchingAddon fitting overage`
- **wire**: `overage macAdapter`

### Assemblies (device-flow presets)

`{id, name, perRun, sourceQty, sections: {sectionKey: [{description, quantity, labor, price}]}, createdAt, updatedAt?}` — device section keys, only for sections that hold a row with substance (a blank row per empty section used to be stored, listed on the card and loaded back out). Created via "Save as an assembly →" in device.js; loaded back into the device temp buffer, not directly into the manifest.

**Editing one** (X8): `TakeoffState.renameAssembly(id, name)` and `updateAssembly(id, sections, sourceQty)` mutate the stored object **in place, keeping its id** — which is the whole point, because the cloud merges assemblies as a union by id keeping whole objects (`TakeoffCloudSync.mergeAssemblies`, local over remote), so an edit travels as an edit instead of arriving beside the copy it replaced. `updateAssembly` re-derives `perRun` from the `sourceQty` it is handed (0 → totals), so re-recording from a line with no run count cannot leave a per-run flag standing over absolute quantities; both stamp `updatedAt`. The card's **Update from this run** builds its rows through the same `recipeSections` helper "Save as an assembly →" uses, refuses an empty flow, and keeps the previous whole object in `preUpdateAssembly` so the flow note can offer **Undo update** (restored via `setAssemblies`, flags and all). None of these — nor Delete — calls `setFlowDirty`: assemblies are not the bid, nothing is waiting on Save, so the Cancel guard deliberately stays quiet after them. There is no link from a saved child back to the assembly it came from (`device.js` writes children with no assembly reference), so a "used on N runs" count is not computable without adding one.

`perRun: true` means each row's `quantity` is a **ratio per run** (the quantity it was saved at ÷ `sourceQty`, the source line's run count), and load multiplies it by the target line's run count, rounding **up** to whole parts. An assembly saved from a line with no run count, and any preset saved before the flag existed, has `perRun: false`/absent: those load at their stored quantities, with a note on the flow page. The flag rides along through the cloud's union-by-id merge (whole objects are kept, cloud.js), so nothing strips it.

### Labor Book (editable "Parts" side)

`laborBook[type][sectionName] = [{name, labor, price, partNumber?, edited?, userAdded?, priceSource?, pricedAt?, offers?, history?}]`. `offers` holds one current quote per supply house (`{supplier, price, at, by}`); `history` is an append-only capped (50) change log (`{at, kind: 'price'|'labor', supplier?, value, by}`), `by` being the signed-in email's short name via `TakeoffCloud.getEmail()` (or `You`). `recordPartPrice` updates an offer and moves the working price when the caller asks (`use`), when the quote is from the supplier already in use, or when no *real* quote is on the row yet — an imported catalog price (`by: 'import'`) and a hand-typed one (`supplier: 'You'`, the `HAND_PRICED` constant) are not quotes, so first-quote-wins survives promotion. It records the canonical spelling of a supplier already on the row, so a badge can't read "summit electric" beside a table's "Summit Electric". `at` omitted means today; `at: ''`/null means **no date recorded**, which is a real answer the badge has a tier for. `usePartOffer` switches the working price explicitly; `updatePartOffer` corrects an offer's date or supplier spelling **without** touching the price (the card's date cells), following the row when that offer is the one in use. `refreshSupplierOffers` syncs promoted parts' vendor offers from the catalog by part #, following the working price only when that vendor is in use. `priceSource`/`pricedAt` (YYYY-MM-DD) record who supplied a price and when: `updateLaborBookRow` stamps `You`/today whenever the price value changes (callers can pass explicit values) **and records that hand price as a real offer plus a history line**, so the commonest way of entering a price leaves a trail; clearing a price clears `priceSource`/`pricedAt` with it, so the row returns to the quiet "+ price" ghost instead of wearing a fresh badge over an empty field. There is no badge popover — the part card (js/views/laborBookCard.js) owns provenance; provenance-only updates (`updatePartOffer`) deliberately do **not** set `edited`, so the row still upgrades with future defaults merges. **Money is parsed once, on the way in**: `updateLaborBookRow` and `recordPartPrice` run every incoming price through `TakeoffUtils.parseMoney` (strips the dollar sign, thousands commas and whitespace), so a stored price is always a numeric string or `''`. Text that is not money is REJECTED — the row is stored unpriced, no provenance is stamped, and `updateLaborBookRow` returns `{priceRejected: true}` so the view can keep the typed characters on screen and flag the field (`input.lb-price-invalid`); the catalog inputs refuse to promote at all. `getBookCorrections` re-normalizes prices on the way out, so a workspace saved before this can never share a string price. Defaults live in `js/data/laborBookDefaults.js` (pure data); state.js deep-clones `LABOR_BOOK_DEFAULTS` at load so user edits never mutate the defaults. Conduit tab has extra grouping config (`LABOR_BOOK_DEFAULT_GROUPS`).

**Provenance + defaults versioning** (js/laborBookMerge.js): `updateLaborBookRow` stamps `edited`, `addLaborBookRow` stamps `userAdded`, and deleting/renaming a default row records its name in a `removed` map — and the mirrors matter as much as the stamps: a row renamed back (or added back under the old name) is spliced out of `removed`, and a row typed back to the shipped values loses `edited`, or the user is left proposing corrections they did not make and frozen out of future upgrades. Only a user action writes `removed`: a default merely missing from an older book is an *inferred* gap and is healed by the merge instead of blacklisted. The stored map is `laborBookMeta: {defaultsVersion, removedV: 2, removed, removedLegacy}` — `removedLegacy` is the pre-split map (written before that distinction existed, so it mixes real deletes with inferred gaps): it still blocks a row from returning, but is never shared as a correction. `mergeDefaults` returns `{changed, updated, added, dropped}`; `updated` — rows whose numbers moved under an untouched user — is what the one-time "the shared parts book was updated" line names (cloud.js `noteBookUpdate`, read once via `TakeoffState.takeBookUpdate()`). The workspace stores `laborBookMeta`; on restore/adopt, a book older than `LABOR_BOOK_DEFAULTS_VERSION` gets `mergeDefaults` (untouched rows upgrade to new defaults, user-touched rows win, removed defaults stay removed) — bump the version constant whenever the defaults data changes. Pre-versioning books are bootstrapped by diffing against the current defaults **and then merged** (a bootstrap must not claim the current version, or an empty/partial book is recorded as up to date with its sections missing and never self-heals). Part names must be unique inside a section: the merge is name-keyed, matches one default to one row, drops surplus untouched duplicates, and refuses a defaults section carrying a duplicate name (laborBookMerge.test.js asserts the shipped data is duplicate-free and merges to `changed === 0`). A merge-only save keeps the stored `savedAt` — only a user edit stamps a new one, so booting after an app update can never win last-write-wins over another device's corrections. The same flags drive `TakeoffState.getBookCorrections()` — the edit/new/remove diff a consenting user shares (see Cloud sync).

### Undo/redo

Snapshot-based (full JSON clone of manifest), 50 deep. `beginBatch()`/`endBatch()` collapse multi-step mutations into one frame; `updateItem` coalesces same-item edits within 1200 ms, skips the frame entirely when every key in `updates` already equals the item's value (`null`/`undefined` count as equal — a blank price re-sent on blur is not an edit), and `undo()`/`redo()` end the coalescing window so the next keystroke starts its own frame. **Manifest only** — laborBook/assemblies/laborRate/taxRate changes are not undoable. The starter row seeded at boot (`seedStarterRow` in app.js) clears the history behind it, so a cold boot has nothing to undo. The header buttons are refreshed by `TakeoffApp.updateUndoRedoButtons()` — called at the tail of `render()` and by the manifest view's `updateSummaryOnly()`, which is the path every edit that deliberately skips a render goes through. Ctrl/Cmd-Z (Shift for redo) is bound in app.js and fires only outside inputs/textareas/selects/contenteditable and with no `.modal[aria-hidden="false"]` open.

### Computed selectors (pure functions over manifest)

`getTotalLabor` (delegates to `getSummaryBreakdown().laborTotal` so the screen and the PDFs cannot disagree), `getPurchaseList`, `getFlattenedItems` (adds `_depth`), `getSummaryBreakdown(manifest, taxRatePercent)` (materials + sales tax + labor + other charges).

**Sales tax is per project, not a constant.** `getSummaryBreakdown` takes the rate as a percent and echoes it back as `breakdown.taxRate`; `DEFAULT_TAX_RATE` (8.5) is only the fallback for a missing or unreadable value, and rates are clamped to 0–100. `TakeoffState.getTaxRate()/setTaxRate()` own it, the project document carries `taxRate`, and the summary's "Sales tax (%)" input writes it.

**Site charges.** `isSiteCharge(item)` — a `trenching` row, or a `trenchingAddon` whose `meta.addonGroup === 'rental'` — bills under `otherCharges.siteWork` (untaxed) instead of materials, and never gets a purchase-list line; its hours still land in the parent run's labor bucket. Fill-material add-ons (`addonGroup: 'fill'`) and legacy add-ons with no `meta` stay materials. `OTHER_CHARGE_KEYS` is the full Other Charges list (the three typed types + `siteWork`) and is what the summary and the PDF iterate.

**One rounding convention.** Both readers round each line's extended cost to cents before summing (`Math.round(qty * price * 100) / 100`), so the summary subtotal and the purchase-list total agree to the cent on 4-decimal supplier prices. Negative prices, hours and quantities are read as 0 by both (the manifest inputs clamp on change; this covers imported and older data).

**One quantity rule everywhere**: quantity 0 contributes 0 to materials, to labor and to the purchase list. (There used to be a "a priced or labored row at qty 0 counts once" branch in the summary while the purchase list dropped the row — the two reports then disagreed by exactly that unit price. Typing a description still sets the quantity to 1, so a row being filled in is never silently worth nothing; the manifest greys the quantity cell of a described, priced row parked at 0.)

**Labor on other-charges rows**: permits / power co. / temporary power rows book their *price* under Other Charges and their *hours* into `labor.other`, which counts in `laborTotal` and prints as the "Other" line in the summary's labor table.

**Where a bucket's hours came from**: `getSummaryBreakdown` also returns `laborByOrigin`, the same buckets as `labor` split `{parent, component}` — hours typed on a top-level assembly row vs hours on its children, split under the *parent's* bucket (a trench child's hours are the run's). The two halves always sum to `labor[bucket]`. The manifest's labor table prints the split in place of the bare number when both halves are non-zero (`11.28 · runs 5.28 + parts 6.00`); one-sided types stay a bare number.

`getPurchaseList` details: lines merge by `TakeoffUtils.descKey` (the one "same description" key, shared with the import preview/merge); a parent with children contributes its own line only when it carries a price (price-less parents are groupings); other-charges types are skipped; overage children never get their own line — they fold into their parent's line by parentId + type (`3/4" EMT Homerun (incl. 10% overage)`, quantity 242), a null-priced overage folding as unpriced quantity. A line bought at several unit prices exposes `unitPriceLow`/`unitPriceHigh` (`priceVaries: true`) and renders as a range in the cell and in the copied TSV; `extended` stays a single exact number.

## Cloud sync (js/cloud.js, `TakeoffCloud`)

Optional Supabase mirror of the book, assemblies, and projects; the app stays local-first (boots synchronously from localStorage, works fully signed out or with the CDN blocked). Supabase project `takeoff-tooling` (`awjcdxqhvgnqsrlnoyxr`, us-east-2): `public.takeoff_store` (`user_id, key, value jsonb, updated_at`) holds the `book` and `assemblies` rows (a legacy `workspace` row is read once as a stand-in for a missing `book` row and left as backup), and `public.takeoff_projects` (`id, user_id, name, data jsonb, created_at, updated_at` — schema-aligned with Count Tooling's `projects` table; SQL in `supabase/001_takeoff_projects.sql`) holds one row per project (`data` = `{manifest, laborRate}`, `updated_at` = the client's savedAt). Both under RLS scoping every operation to `auth.uid() = user_id`. Roles live in `takeoff_profiles` (`user`/`admin`/`dev`, 002 migration): `admin` unlocks the suggestions review (via `is_takeoff_admin()`, now role-driven with the hardcoded-email check as a pre-002 fallback), `dev` additionally gets Manage Users (list/set-role RPCs + the `takeoff-admin` Edge Function for create/delete, which re-verifies the caller's dev role server-side). Projects sync per-row and union-merge on sign-in, but never by clock alone: every device records the remote `updated_at` it last reconciled with per project (`takeoff-cloud-seen`), and js/cloudSync.js uses it as the common ancestor. A copy no newer than that stamp is an untouched pull and may be replaced; anything else is a real divergence, and then **both** copies are kept — the row keeps the newer bid and the loser is written back as a separate project named `<name> (conflict — <device time>)` (pushed to the same account), with one dismissible line under the header saying so. There is no merge dialog. Pushes carry the same precondition: `takeoff_upsert_project` (supabase/003) writes only if the row still carries the stamp this device saw, and where 003 is not applied cloud.js falls back to read-compare-then-upsert (same decisions, not atomic). A missing `takeoff_projects` table (SQL not yet applied) disables project sync gracefully. `data` carries the whole project document minus its identity (`manifest, laborRate, taxRate, details, importedFrom`), and `TakeoffCloudSync.sameContent` compares all of it — a change to any one of them must not read as "already in sync". Two rules keep the junk out: the empty starter every boot mints (no row with a description — `shouldPushNewProject`) never earns a cloud row, and on a device whose open project is such a starter, sync switches to the account's most recently updated remote bid (`pickProjectToOpen`), including the one rebuilt from a legacy cloud workspace — otherwise the first sign-in on a new machine lands on an empty table with a checkmark on it. **Deletes travel** as a `deleted` row in `takeoff_store` (`{v:1, projects:{id: at}, assemblies:{id: at}}`, written by `onProjectDeleted` and by an assemblies save that dropped an id): the union honours it, tombstoned index entries and local project documents are dropped, and a resurrected remote row is deleted again. A copy saved *after* its tombstone wins. No schema change was needed, and assemblies — which have no table — are covered too (see supabase/README.md).

**Shared-book corrections** (opt-in; consent is the account's — a `share` row in `takeoff_store` (`{v:1, on, at}`), read at sync and never a browser flag, so two devices agree, either can withdraw, and consent does not outlive a session on a shared machine; the old `takeoff-share-corrections` key is deleted on sight): after each workspace push, `TakeoffState.getBookCorrections()` is upserted into `public.takeoff_suggestions` (`user_id, email, tab, section, part_name, kind edit|new|remove, old_value, new_value, status pending|accepted|dismissed`; unique per user+part; RLS: users see only their own rows, `is_takeoff_admin()` — email match — sees all). Reverted edits are pruned on the next push; opting out deletes the user's rows. The admin account gets a "Review suggestions" ☰ menu item (js/suggestionsReview.js): pending rows aggregated per part (distinct users, medians, and two guards: a ≥20× outlier on **hours or price** for an edit and absolute bounds for a `new` part, plus a chimera flag when a two-user group's median hours and median price come from different people — a flagged group can still be accepted, but only through a confirm), Accept/Dismiss updates status, and "Download accepted as defaults patch" emits JSON to apply to `js/data/laborBookDefaults.js` + version bump and then marks those rows `shipped`, so each patch is a delta rather than a re-apply. A `new` correction carries its `partNumber` (inside `new_value`, no schema change) or the maintainer has nothing to key the catalog on — the shared book only changes through a commit, like the supplier-price flow. A `takeoff_suggestion_summary` view exists for reviewing straight from the Supabase dashboard. **A promoted catalog part is not a correction**: `promoteCatalogPart` stamps `userAdded`, which would otherwise emit the supply house's own catalog price (usually with `labor:0`) as a brand-new part, so `getBookCorrections` filters rows `TakeoffCloudSync.isUnquotedPromotion` recognises — `userAdded`, every offer `by:'import'`, no hours, no non-import history line. Hours or any human-authored offer (a quote, or a hand-typed price, which lands as the `You` offer) releases it. The hours test is load-bearing because `updateLaborBookRow` deliberately never stamps `edited` on a `userAdded` row. Auth is Supabase email/password with an email OTP fallback (6-digit code — the "Magic link or OTP" email template was edited to send `{{ .Token }}`) that self-provisions the account (`shouldCreateUser: true`), so **Manage users is a directory, not a gate**: `adminCreateUser(email)` sends no password at all (the Edge Function still accepts one for older callers), and passwords are the account's own — `auth.updateUser({password})` behind "Set a password" / "Change password" in the cloud dialog, and `resetPasswordForEmail` behind "Forgot your password?", whose link returns to `origin + pathname` with a recovery session on it (`PASSWORD_RECOVERY` → `recoveryMode` → the new-password form). That reset link is the **one** thing needing a Redirect URL allow-list entry in the dashboard (supabase/README.md); sign-in itself still needs none, so localhost and GitHub Pages behave identically. `fetchProfileRole` is also exposed as `refreshRole()` and re-run on every `syncDown` and after `setUserRole`, so a role change no longer waits for a sign-out. Sync rules: on sign-in, workspace conflicts resolve by newest `savedAt` (last write wins) and assemblies merge as a union by id; afterwards every `TakeoffStorage.save*` queues a debounced (1.2 s) upsert, flushed when the tab hides. **Lid-close**: `pagehide`/`beforeunload` run `flushPendingOnUnload`, which asks `TakeoffCloudSync.buildKeepalivePushes` for plain PostgREST requests (session access token + the shipped publishable key) and fires them with `fetch(..., {keepalive: true})` so they outlive the page — store rows as the same merge-duplicates upsert, projects through the same `takeoff_upsert_project` guard (skipped, never blind-upserted, when 003 is unapplied), with the written stamp recorded in `remoteSeen` first so the next boot does not fork the bid against its own push. The builder is pure and unit-tested (cloudSync.test.js); anything over the browser's shared 64 KiB keepalive budget is deferred to the ordinary flush. Pulling remote data goes through `TakeoffState.adoptWorkspace` / `setAssemblies` (clears undo history) + `TakeoffApp.render()`. The publishable API key ships in cloud.js by design; RLS is the access control.

## Telemetry (js/events.js, `TakeoffEvents`)

One call — `TakeoffEvents.log(name, props)` — at each measured moment. Fire-and-forget: it queues, never awaits, never throws, and the queue flushes every 5 s, at 20 events, and on `pagehide` (a `keepalive` fetch). A batch that cannot be sent is **dropped, never retried**. Rows land in `public.takeoff_events` (`supabase/004_takeoff_events.sql`) by plain PostgREST POST, using the Supabase URL + publishable key read from `TakeoffCloud.getEndpoint()` so they live in one file; the bearer token is the signed-in session's when there is one, otherwise the publishable key.

**What is sent**: the event name, a small props bag, `install_id`, `vw` and `coarse_pointer`, and `user_id` **only while signed in**. The install id is a random UUID in `takeoff-install-id` — anonymous, per browser, not an account and not a fingerprint.

**What is not sent**: descriptions, project or job names, per-row prices, emails, addresses, plan pages, search terms. The guard is `sanitizeProps`, not the call sites: a value survives only if it is a boolean, a finite number (2 dp) or a short spaceless enum token (`/^[A-Za-z0-9_.:+-]{1,32}$/`), and keys on a deny list (`description`, `name`, `email`, `price`, `total`, `client`, `query`, …) are dropped whatever they hold. A row description like `3/4" EMT` fails on the space and the quote, so it cannot leave the browser even if a call site passes it by mistake. `events.spec.js` asserts the absence of the seeded description in the actual request body.

**When it says nothing at all**: the migration is unapplied (404 / `42P01` → silent for the session), the endpoint refuses us (401/403), the device is offline, Do-Not-Track or Global Privacy Control is set, or `localStorage` carries **`takeoff-telemetry-off`** (any truthy value) — the user-facing opt-out. It is also silent under automation (`navigator.webdriver`, the same guard the service worker uses) so the Playwright suite files no events; `events.spec.js` opts itself back in with `takeoff-telemetry-test`.

First event set (one line per site): `session_start {vw, vh, coarsePointer, standalone}` (app.js boot) · `flow_saved {kind, rows, componentPrice}` (device/conduit/wire Save) · `book_add_to_target {door, bucket, exploded, inheritedQty}` (laborBookTargets.js, all three add paths) · `import_added {mode, raised, added, lowered, untyped}` (import.js `performImport`, computed **before** the write — afterwards the matched rows already carry the new counts) · `purchase_list_generated {lines, unpriced}` (manifest.js toggle) · `pdf_exported {variant, rows, pages}` (all three pdf.js exports) · `share_link_created {rows, hasRate}` / `share_link_opened {rows, hasRate}` (app.js) · `project_switched {fromView, flowDirty}` (projects.js, captured before the flow editor is left) · `undo {frames, fromView}` (app.js button + Ctrl-Z; `frames` is `TakeoffState.getUndoDepth()`, the stack depth before the pop).

Standing rule, borrowed from Count Tooling: **every rework ships its own event.**

## View pattern

Every view exports `{ render, attachListeners }`. `TakeoffApp.render()` switches on `TakeoffState.getCurrentView()` (`'manifest'|'device'|'conduit'|'wire'`), sets `#main-content.innerHTML = View.render(...)`, then calls `View.attachListeners(...)`. Nearly every interaction triggers a full re-render; listeners are re-bound wholesale each time (exceptions: laborBook module-init one-time listeners, a few delegated handlers in laborBook/mcBook, and `TakeoffManifestView.updateSummaryOnly()`, which patches the summary and any open purchase list).

**Never rebuild a block a field edit sits in.** A field's `change` fires between mousedown and click, so replacing a node there destroys the control the estimator is aiming at: the click lands on nothing and focus falls to `<body>`. `updateSummaryOnly()` therefore writes `textContent` into the summary's `[data-summary]` cells (never `outerHTML`), refreshes only the purchase list's meta line and `.purchase-list-body` (its Copy/Hide buttons live outside that), and the labor-rate input is bound once by delegation on the stable `#main-content` host instead of re-bound per render. Row-button handlers read `e.currentTarget.dataset.id`, never `e.target` — a click at an icon button's centre targets the `<path>` inside it, which carries no id.

## Flow editors (device / conduit / wire)

Shared pattern: `TakeoffApp.navigateToX(itemId)` hydrates a per-flow **temp buffer** in TakeoffState from `parent.children` (mapping child `type` → section); the view edits only the buffer; save strips the relevant child types from `parent.children` (direct mutation) and re-adds each meaningful row via `TakeoffState.addItem(..., parentId)`, wrapped in `beginBatch()/endBatch()`. `navigateToManifest()` clears all temp buffers.

- **Device**: single page, 8 sections, ×2/÷2 qty helpers, Save-as-an-assembly + assemblies browser. **A section with no rows renders as a chip, not a table** (`.device-section-chips`): `navigateToDevice` seeds no blank rows, the chip's click adds the row and focuses its description, and emptying a section folds it back to its chip. **Component quantities are totals for the whole line, not per run**: a row added on an N-run line is seeded at N, the column head says "Quantity (all N runs)" and the panel prints the per-run price beside the extended one (there is no summed component Quantity — receptacles plus boxes plus covers is not a count of anything orderable). Field edits commit to the buffer on `input` and patch the totals panel in place — nothing in this flow re-renders on `change`, because doing so destroyed the control under the pointer and swallowed the first click after typing. Save compares the rows it would write against the parent's existing children: **an unchanged save is skipped entirely** (no undo frame, no new ids) and otherwise a surviving row keeps its child id (matched on type + description). "Load into Ledger" replaces every section, so it keeps the previous buffer in `preLoadBuffer` and the flow note offers **Undo load** whenever the load replaced anything; `setDeviceTempData` merges, so the load writes all 8 section keys. Each assembly card also carries **Update from this run** and **Rename** beside Load and the trash (see Assemblies above); the flow note holds at most one way back at a time — `showFlowNote(msg, {id, label, run})`. The flow row's only book door is the **Book** button (fill mode) — the per-row book icon and the `targetDeviceRow` "Add to" merge path are gone.
- **Conduit**: 3-step wizard (Trenching → Fittings → Overage), step inferred from existing children on entry. **Next, Back and the step pills are pure navigation** — trenching, add-ons, fittings and overage are all written in the single `beginBatch()/endBatch()` on Save (one undo frame per run), so Cancel on any step really cancels. A run with no footage, material, depth or price per foot gets no trenching child at all. Trench add-ons come in two button groups with their own tables and units — **Rentals** (hours or days · rate) and **Fill & site** (quantity · unit price) — and the group is recorded on the child as `meta.addonGroup: 'rental'|'fill'`, which is what the summary reads to tax fill as stock and leave rentals out of it; rows saved before the split carry no group and the wizard re-derives one from the description (unrecognised → `'fill'`). Fitting presets come from `FITTINGS_LIST`, and picking one fills the blank seed row rather than appending below it. Legacy items without `meta` are re-parsed from description strings.
- **Wire**: overage % + MAC adapters (Description / Quantity / Labor / Price, same columns as the conduit fittings table).
- Both conduit and wire print `TakeoffViewShared.renderParentSummary(item)` (one length line, with its unit) and `renderOverageSection` (the chosen preset % carries `.active` / `aria-pressed`; `updateOverageTotal` re-marks it as a custom % is typed). Money and hours in flow inputs are rendered through `TakeoffUtils.formatMoney` / `formatHours` minus the thousands separators a `type=number` field rejects, so a supplier's `58.4697` reads `58.47`; number inputs carry `inputmode="decimal"`.

A flow's temp buffer is keyed on a row id from the **open** project, so anything that swaps the manifest underneath it has to leave the editor first: `TakeoffProjectsView.switchTo` and `createFromRow` (the header switcher, Manage → Open, and both New-project paths) call `TakeoffApp.navigateToManifest()` and **abandon the switch** if the estimator keeps their edits; `handleHashRoute` does the same for `#d=` links. As a backstop, `TakeoffApp.render()` falls back to the manifest whenever a flow view's item id no longer resolves, and `duplicateProject` / share-link import re-id every row (children's `parentId` remapped) so a bid and its twin can never key the same editor.

**The projects surface** (views/projects.js) reads `TakeoffState.getProjects()` (sorted by `updatedAt`) but renders it through `switcherProjects()` / `projectFacts()`, which pin the **open** bid to row 1 of both the switcher menu and Manage projects — the stamp also fires on leaving a bid, so an unpinned list never has it where you last saw it. A rename does **not** stamp: for a non-open bid `applyRename` rewrites `name` in the project document and the index entry and leaves `savedAt`/`updatedAt` alone (a rename is not an edit to the bid, and stamping moved it to row 1); as a consequence a rename of a *closed* bid does not move its cloud clock either. Names render through `middleEllipsis` (the suffix is what distinguishes three bids on one building) with the full name on the `title`, and a trailing `(copy)`/`(shared …)` — legacy naming, current code appends ` 2`, ` 3` instead — renders as a chip. The Lines column counts parents **plus** their children, read from `TakeoffState.getManifest()` for the open bid so it is not one 400 ms debounce behind. Delete confirms inside the row (no `confirm()`), with the line count in the sentence; the open bid keeps a **disabled** Delete carrying the reason. `#project-switch-btn` shows the bid name over a "Saved …" line from `fmtAgo` (minute-grained: *just now* / *N min ago* / *today* / …), refreshed every 5 s, and appends "· synced HH:MM" when `TakeoffCloud.getLastSyncedAt()` exists and the user is signed in — cloud.js does not export that getter yet, so the suffix simply does not render. `openModal({create:true})` is the "name this job" route: Create clears the field and **closes** the modal, Escape in the field closes it too, and when the open bid is untouched (`openBidIsPristine`: still "Untitled project", no described or typed row, no children, rate 0) the name is applied to it instead of minting a second bid.

**Archive** (X9) is the closed-out state for a bid: `TakeoffState.setProjectArchived(id, bool)` writes `archived`/`archivedAt` to the project document **and** mirrors them onto the index entry. It stamps the document's `savedAt` — that stamp is what carries the change to the account's other devices — but deliberately leaves the index entry's `updatedAt` alone, so "Last edited" and every `updatedAt` ordering stay put. The open bid can't be archived (the state call returns `false`, and the row's Archive button is disabled with the same reason Delete gives); it can always be unarchived. `switcherProjects()` drops archived bids from the header menu (the open bid is always listed, archived or not, or the menu would mark nothing as current) and the menu footer grows an "N archived" line that calls `openModal({archived:true})`. Manage projects renders a `Live` table plus an `<details id="projects-archived">` section, collapsed until asked for (`archivedOpen`, remembered across re-renders; archiving one opens it so the row does not just vanish), sorted by `archivedAt` desc. `duplicateProject` and share-link import build their documents field by field, so neither can produce an archived bid; a cloud conflict copy (`keepConflictCopy`) is likewise live, so the copy the estimator is being told about is visible in the switcher.

The discard guard (`TakeoffState.getFlowDirty()`, asked by `navigateToManifest` and by the header's Undo/Redo before either moves the manifest) is armed by every write into the conduit/wire buffer, including the ones `views/laborBookTargets.js` makes directly. `setCurrentView` opens a hydration window that `TakeoffConduitView.render` / `TakeoffWireView.render` close with `TakeoffState.endFlowHydration()`, so `navigateToConduit`/`navigateToWire`'s own buffer fill does not count as an edit.

`TakeoffViewShared.syncDerivedChildren(idOrItem)` reconciles a row's derived children at **write time** (call it right after `TakeoffState.updateItem` in the manifest's `handleFieldUpdate`; nothing is derived at render, because pdf.js, share links and the selectors all read the stored child): a parent edit recomputes each overage child that still carries `meta.overagePercent` from the parent's current quantity/price; an edit to the overage child itself drops `meta.overagePercent`, sets `meta.overageManual` and relabels it `... (manual)`; an edit to a trenching child writes `meta.feet`/`meta.pricePerFoot` and regenerates its description via `TakeoffViewShared.trenchDescription`. It mutates in place and relies on the caller's `updateItem` for the undo snapshot and the debounced save.

Per-row "Book" buttons (class `part-book-icon-btn`) in the flow editors open the Labor & Price Book in **fill mode**: fill-target kinds are `{kind:'manifest-row'|'device-row'|'conduit-fitting'|'wire-mac', ...}`; the picked part fills the clicked row in place (`TakeoffLaborBookView.addEntryToTarget`).

**The book link on a bid row (X1).** `addEntryToTarget` resolves the entry's description back to the book row it came from (`resolveBookRef` in views/laborBookTargets.js — an exact match on `describeBookRow(name, section)`, `null` if nothing or more than one row answers to it) and stamps `meta.book {type, section, name, partNumber?}` on the manifest row it adds or fills. No caller passes the reference; an Elliot catalog part or an exploded assembly resolves to nothing, which is correct — there is no single book row to watch. The manifest view (`bookDelta`) compares that row's in-use price to the bid row's on every render and inside `updateSummaryOnly`, and draws a `book: $X` chip in the price cell **only** when they differ to the cent; clicking it writes price (and labor, when the book's hours changed too) in one `beginBatch` frame. The chip lives in a `.book-chip-slot` span that is patched in place, so it can appear and go while the estimator is typing in the price field.

**Manifest row controls.** The type chip is two doors: its **text** opens the type picker (`.type-badge-text` → `TakeoffApp.showTypeModal`, with `data-type=""` = "No type" at the bottom of the modal handled by `TakeoffModal.handleTypeSelect`), and on a flow row a pencil beside it (`.type-badge-flow`) opens the editor in one click. There is no clear-type ×. The **trash** is on every row (`.remove-cell`), `opacity: 0` until `tr:hover`/`tr:focus-within`, and unconditionally visible under `(pointer: coarse)` or ≤ 640 px; the "Remove items" ☰ mode and `showRemoveIcons` are gone. Both are `.row-btn`, so they are in the row's roving-tabindex group.

## Import / export formats

- **CountTooling clipboard import** (import.js): one line per row, tab-separated `fixture \t count \t page`. Type inferred by ordered word-boundary rules on the description (`TYPE_RULES`; gear compounds like *transfer switch* are tested before `switch`, lighting before generic `panel`). A trailing `View link: \t <url>` footer line is dropped, not imported. Both import paths land in the same preview modal.
- **Import preview** (import.js): one state-aware primary button — `Add N fixtures` / `Update N counts · add N fixtures` / `Nothing to change` (disabled) — built from the pure `summarizeImport` + `primaryLabel`. Counts are **totals in both directions**: a matched row is set to the import's count (up or down) and takes the import's plan page; price and labor are untouched. `Add as separate rows` (a demoted text action, hidden unless a line matched) is the old Add All. Rows carry a type picker; unreadable counts render `× ?` and land as 0. Matching uses `TakeoffUtils.descKey` — the purchase list's key — at every site. Whole import = one undo frame, including the blank starter row it consumes when the bid is otherwise empty.

### The `#import=` contract (for Count Tooling implementers)

`<app>/#import=<base64 of a JSON payload>` — read at boot and on `hashchange`, hash stripped via `replaceState` before the preview shows (import.js `importFromPayload`, app.js `handleHashRoute`).

```
{ v: 1, source?: string, items: [{ description, count|quantity, page|planPage?, type? }] }
```

- `v` **must be the number 1**, pinned literally. Any other value is refused with a message naming the version it saw — it is not reported as an empty link.
- `description` — required, trimmed; blank items are dropped silently. It is the merge key: normalized as trim → lowercase → internal whitespace collapsed (`TakeoffUtils.descKey`), the same key the purchase list merges on.
- `count` or `quantity` — a number or a numeric string. `$`, commas, quotes, spaces and a trailing unit are stripped (`"1,800"` → 1800, `"220 ft"` → 220). Anything else is *unreadable*: the preview shows `× ?`, a matched row keeps its count, and a new row lands at 0.
- `page` or `planPage` — optional free text. On a matched row it replaces a stale page.
- `type` — optional, compared **case-sensitively** against `ITEM_TYPES`: `lighting gear devices conduit wire specialSystems permits powerCoCharges temporaryPower`. Anything else (including `Gear` or `receptacles`) falls back to inference, and the estimator can correct it in the preview.
- A description starting `px of ` means the plan page was never scaled upstream; the preview flags it as pixels, not feet.
- Payload too large / corrupt base64 → *This import link could not be loaded*; no items → *This import link contained no valid items*. Nothing is written to the bid in either case.
- **Copy share link** (app.js `buildShareEnvelope` / `copyShareLink`, button under Print Options — it is not in the ☰ menu): `#d=` + base64 of `{v:2, app:'takeoff-tooling', exportedAt, name, laborRate, taxRate, details, manifest}`; on load, hash import sanitizes recursively (`sanitizeImportedItem` / `sanitizeDetails`) and lands in a NEW project named from the payload (nothing is replaced), then strips the hash. `laborRate` and `taxRate` are applied (`setLaborRate` / `setTaxRate`) only when they are numbers, so both people read the same grand total; links made before either existed still inherit the recipient's own rate (and 8.5% tax). Import accepts the envelope or a legacy bare array; `v` is ignored. **Imported rows always get fresh ids** — reusing the sender's ids let a shared copy and its source share row ids, which an open flow editor keyed on.
  - The copy is stamped with `importedFrom {name, exportedAt}`, so **opening one link twice reopens that copy** (`findImportedProject`) instead of creating an identical twin; a genuinely new link for the same job takes the `' 2'` suffix from `uniqueProjectName`, which `duplicateProject` uses too. The recipient gets a dismissible `#app-notice` bar — *Copy of X, shared Sep 6 by link — edits stay on this device* — dated from the sender's `exportedAt`, not from the day it was opened. A shaped-but-empty payload (missing or non-array `manifest`) and a corrupt one both say so in that bar rather than in an `alert()`.
- **PDF exports** (pdf.js): review, purchase list (PO), with-form. Manual jsPDF layout, letter format. All three are saved as `<project slug>-<kind>-<YYYY-MM-DD>.pdf` (`fileName`/`slug`; `/` and `:` collapse to `-`). Money comes from `TakeoffUtils.formatMoney` and hours from `formatHours`, so no PDF prints a number the screen would not.
  - *Print for Review* is two parts: page 1 is the manifest summary in the screen's words and order (MATERIALS / LABOR / OTHER CHARGES / Grand Total, dollars with cents), page 2 on is the line-item table. Its "Labor TOTAL (hrs)" is `getSummaryBreakdown().laborTotal` — the number the screen shows — not `getTotalLabor()`.
  - The table's eight columns (`REVIEW_COLUMNS` in pdf.js) are measured boxes summing to the 532 pt text width; every cell is wrapped to its box with jsPDF's `getTextWidth` (`wrapToWidth`, which breaks an over-long token by character), so no run can reach its neighbour. `PURCHASE_COLUMNS` and `FORM_COLUMNS` use the same `layoutRow`/`drawRow`/`drawTableHeader` engine. Type labels come from `TakeoffManifestView.TYPE_LABELS` / `CHILD_TYPE_LABELS` / `SUMMARY_LABELS`, exported for this. Hours print at two decimals; extended hours and extended price use the summary's `× quantity` rule so the columns add up to page 1.
  - *Purchase list (PO)* is `TakeoffState.getPurchaseList()` on paper — the same merged report the screen shows, in the same columns (Qty · Material · Unit $ · Extended $), with the project name and date at the top, `n materials · n without a price`, and the materials total before tax. The button, the on-screen report and the PDF all read "Purchase list (PO)". It is not the manifest tree: price-less grouping rows, permits and power-company charges are not on it, and duplicates are merged.
  - *Print with form* takes `TakeoffState.getProjectDetails()` and prints the filled ones (Client / Address / Permit no. / Builder or occupant / Due date) **under the project name on page 1**, above the line items — never as a footer after the last row. It asks nothing: there is no form modal.

## Labor & Price Book modal (two sides)

- **Parts** (views/laborBook.js): editable per-tab sections from `TakeoffState.getLaborBook()`, woven together with the supplier catalog by views/laborBookElliot.js — sections are universal: each supplier catalog section merges by name (case-insensitive) — into a matching curated section as a collapsed "Supplier parts" block below the curated rows, into a matching curated group (conduit tab) as a "Supplier parts" section at the end of the group, and otherwise renders standalone beside the curated ones (styled at group level on grouped tabs so the top-level list stays uniform). Supplier attribution is per part (the provenance badge, `TakeoffViewShared.renderPriceProvenance`: source · age with freshness tiers <30d/30–90d/>90d; supplier entries date from `McBook.elliotImportDate()` until they carry per-part `pricedAt`). Clicking a row's badge (or a catalog part's name) opens the **part card** (views/laborBookCard.js): per-supply-house offers with Use, a record-quote form, and named history; Catalog rows render as live inputs (same columns as curated rows); the first edit — inline or from the card — **promotes** the part into the editable book in its universal section (`TakeoffState.promoteCatalogPart`) with the edit applied, after which its catalog row is superseded (deduped by part #) and its vendor offer refreshes from the catalog on load. An always-visible tab-level filter narrows curated rows and supplier parts together (laborBook.js `applyTabFilter` → `partsEl._elliotFilter`). On tabs with no curated sections (lighting/devices/specialSystems) the "no sections yet" block is demoted to a footer below the catalog sections.
- **Assemblies** (mcBook.js): fetches `mc-assemblies/mc-labor-book.json`, patches with the local Elliot overlay (`McElliotState.getPatchedBook`), renders a lazy level1→level2→section tree. An entry explodes into its components (`getComposition` via `mc-price-model.json`) **only when `compositionReconstructsBook` holds** — every component priced, and their extended sum within `PRICE_TOLERANCE` (±10%) of the book price; otherwise the rolled-up entry lands at the book's own labor and price, which is what the BOM footer promises. Unpriced components carry `price: null`, never 0. `addAssemblyEntry` flashes which price was used under the apply-to banner (`TakeoffLaborBookTargets.flashTargetNote`), appending where it landed and at what count (`getLastTargetNote`). Fill mode always uses the rolled-up entry. `#mc-book-search` filters the tree per tab ("N matching sections"), and section names carry a `title` decoded from `McBook.ABBREVIATIONS` — the same table the Abbreviation Key modal is generated from (js/views/laborBook.js `renderAbbreviationKey`).
- **Search** (views/laborBookSearch.js + `TakeoffUtils.makeSearchRanker`): one ranker per query, used by the global search, the Parts tab filter and the assemblies tree. Every token must match, in any order; a token also matches its synonym group (`SEARCH_SYNONYMS`) and multi-word phrases rewrite the query (`SEARCH_PHRASES`: `exit sign`↔`exit light`, `4 square`↔`4s`/`1900`, `single pole`↔`1p`/`sp`, `circuit breaker`↔`cb`). **Only the spelling the estimator typed may match inside a word** (and only at 4+ characters); anything reached through a synonym must be a whole word, so `support`→`supp` finds "BOX SUPP BRKT" and not "POWER SUPPLY". The score (1 + literal-token hits + phrase-in-order + starts-with) sorts each bucket best-first via `rankedByScore`, which is what makes the abbreviations safe to have at all. Buckets are named for what they carry — *Your book (hours)*, *MC assemblies (hours + material)*, *Supply house · Elliot (prices)* — and fill mode puts your own book first. `Esc` inside the modal is owned by one document-level handler (laborBook.js): it clears the global term, then the assemblies filter, then closes; `TakeoffApp.hideLaborBookModal` clears both, so the book never reopens on a stale term with its tabs hidden.
- **Which quantity a part inherits** (views/laborBookTargets.js): `inheritedQtyFor` multiplies by the parent's quantity only for `gear`, `lighting`, `devices` and `specialSystems` — types whose quantity is a count. Conduit and wire parents (whose quantity is footage) get 1, in the single-add path, the assembly-explosion path and the conduit wizard's fittings branch alike. `describeBookRow` always appends the section, so an elbow and a coupling that share a book name stay distinguishable on the bid and in the purchase list.
- **Pricing a fixture from its own book row** (views/laborBook.js `canPriceFixture`): when the book was opened from a top-level, childless row that carries its own price and a count-typed type, Add on a book row of that same type routes through the fill target `{kind:'manifest-row', keepDescription:true, priceSource, pricedAt}` — price and labor are replaced, the estimator's description survives, and provenance lands on `item.meta`. "Add as a part underneath" is the banner's secondary action and resets whenever the banner points at another row.
- **Update Supplier Prices** (mcElliotUpdate.js): parse vendor CSV → dedupe → match against MC items (saved mappings first, then token-index fuzzy matching in chunks) → build overlay → auto/review/summary tabs → download buttons to commit updated JSON back into `mc-assemblies/`. See [DATA-PIPELINE.md](DATA-PIPELINE.md).

## Known quirks

- **Bump `CACHE_VERSION` in `sw.js` on every deploy that changes a shell file.** Navigations and shell assets are network-first, so an online visitor gets fresh code anyway; the stale risk is the offline copy, which stays whatever the last install wrote until the version string changes and `activate` deletes the old caches. "Reload app (keeps your data)" is the manual escape: it deletes every cache *and* unregisters the worker before `location.replace`, or the reload would just be served the old shell back.
- The service worker is **not** registered when `navigator.webdriver` is true. Every Playwright context is a fresh profile, so otherwise each unrelated spec would pay for an install and could race a `controllerchange` mid-test. `offline-shell.spec.js` registers `sw.js` by hand and exercises the real file; nothing else in the suite sees a worker.
- The page's `beforeunload` (js/app.js) flushes both documents and `TakeoffCloud.flushPending()`, and sets `returnValue` **only** when a flow editor is dirty and the view is not the manifest — every in-app exit already asks, so a tab close or a Cmd-R asking too is the consistent behaviour, not a new one. "Reload app (keeps your data)" (the old Hard reload) unloads via `location.replace`, which skips that handler, so it runs the same confirm itself.
- Export envelope is `v:2`, workspace persistence is `v:1`; neither has real migration logic (`restoreWorkspace` silently drops anything not `v===1`).
- `getItemById` reaches depth 2 only; `sanitizeImportedItem` recurses arbitrarily deep — grandchildren would import but be unreachable.
- `TRASH_SVG`/`BOOK_SVG` constants duplicated verbatim in manifest.js, device.js, conduit.js; overage render/save logic near-duplicated between conduit step 3 and wire.js; blank-row-reseed idiom repeats across flows.
- css/styles.css is one ~4,100-line file organized by `/* section */` comments. Two rules in it are load-bearing across features: a base `[hidden] { display: none !important }` near the top (the UA's bare `display: none` loses to any class that sets `display: flex/block`, which is how four different rows kept rendering while marked hidden — never add a per-class `[hidden]` patch), and `.lb-parts-scroll`, the strip the book's part tables must sit inside because `.labor-book-section` is `overflow: hidden` (a bare `min-width` on the table is clipped, not scrolled). Below 640 px `.lb-parts-scroll` turns each row into a card — the part name on its own line, the fields flowing under it. **The last section of the file is deliberately last**: the projects surface and the phone rules (`(pointer: coarse)`, ≤ 640 px, ≤ 900 px) correct desktop rules of *equal* specificity — the 4.25 rem Labor/Price width, the 14.4 px input size, `.import-preview-modal-content`'s `min-width` — so they only win by source order. Keep additions to it at the bottom. Three things in that block are load-bearing: below 640 the manifest card is `display: flex` with explicit `order` per `td` (the quantity takes a whole line, or the two 24→44 px spinner buttons leave it nothing), the flow's `.flow-actions` is `position: fixed` at the bottom below 900 px (with `padding-bottom` on `.flow-page` to clear it), and `.project-menu` is anchored to `header` (which is `position: relative` below 900 px, with `.project-switch-wrap` static) — anchoring it to the button's own box widened `window.innerWidth` to 455 on a 375 px screen.
